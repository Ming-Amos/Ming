After an AI says a feature is done, someone still opens the application, clicks through the requirements, captures failures, explains them to the coding assistant, and repeats the process after the next edit.

Ming makes that verification loop reusable. It is a local acceptance workspace for developers and small teams building web applications with AI. It connects a reviewed standard to real browser behavior, original evidence, and the coding agent's next action.

Start your development application, register its local URL or a self-contained HTML file, and save the requirements. Write an acceptance plan without a model API, or configure a compatible provider to propose a draft. Review the conditions, dependencies, operations and expected outcomes before confirming. Editing the requirement or standard requires a new confirmation; previous records remain available.

Ming executes the confirmed plan in a real browser. Its English Evidence Studio places requirements, actual steps, expected behavior and observations together. A recorded-step scrubber with Play/Pause follows saved actions and available captures. Focus mode gives evidence more room; Ctrl+K opens workspace commands. A repair slider reveals the original before-and-after screenshots, with links to inspect each original. Playback explores recorded evidence rather than executing another check or inventing missing images.

A connected coding agent can use Ming's 12 MCP tools to discover projects, run an approved plan, read failures, claim a repair task, edit the target application, and rerun the original standard. Creating a task does not automatically wake an editor. Runs support cancellation, history and portable reports.

Ming distinguishes passing acceptance from stronger repair proof. Live local URLs are observed as running applications; a source-folder hash does not prove which bytes the server executed. Self-contained HTML uses a captured document. Strict verified repair additionally requires matching plan, runner and target identities, changed source, complete passing results, and preserved baseline evidence.

The new English Shipboard demonstration records Codex using actual stdio MCP to fix a persistence defect in the same target. Task creation passed, reload lost the task, and blank names were rejected. After the source edit, all three original criteria passed and the comparison returned a verified repair. Twenty-one evidence checks passed; older records remain unchanged. A separate English own-project browser review passed 32 checks covering registration, manual plans, real runs, history and cancellation. The current Evidence Studio and compiled read-only viewer passed 47 interaction and evidence checks.

The supported workflow is local, same-origin web development. Cross-origin requests and redirects are blocked. No external model provider has been configured or quality-tested; manual plans need no model API. The hosted viewer replays reviewed evidence, while new execution runs locally.
