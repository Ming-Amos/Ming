## 2. Implement the selected visual form

Build a light, spacious application X-ray around **one selected criterion**. Keep project/run selection and primary actions visible. Task, run and comparison are states of one coherent workspace, not three unrelated dashboards.

- **Center:** the selected run's real screenshot, largest visual element. Below it show the next observed state when evidence exists. Each image identifies run, criterion/step and capture context; allow opening the original. Before evidence exists, show a clear empty state, not the concept image as a fake execution.
- **Left:** requirement source, confirmed criterion/version, prerequisites, expected behavior and actual action steps. Selecting a criterion updates the whole view.
- **Right:** observed failure/expected-versus-actual details, available console/request evidence, screenshot links and repair task. Missing network evidence reads “not captured”; never invent the reference image's POST/GET events. Separate tentative explanations with dashed amber treatment and “unverified.”
- **Connections:** link actual criterion, step and evidence records. Point into specific screenshot controls only when recorded geometry supports it; otherwise connect cards without invented coordinates.
- **Comparison:** show original and rerun evidence, target source change, plan/test versions and resulting criterion changes. A screenshot after refresh is not a post-repair screenshot. Changed standards or incomparable targets must remain explicit.

Use readable Chinese text, restrained borders/shadows, indigo selection, red verified failures and green verified passes. Add text/icons alongside color. Keep keyboard focus visible, prevent overlapping connectors/text, and stack sections on narrow screens. No decorative scores, fake percentages, elaborate zoom/drag system or city/factory metaphor.
