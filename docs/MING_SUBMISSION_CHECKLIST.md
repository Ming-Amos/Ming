## 2. 两份说明的内容提纲

### Problem & Solution Statement

1. 明确问题：AI 宣布完成后，用户仍要手动点击、截图、解释错误，每次修改后再次检查。
2. 用户：使用 AI 开发网页项目的独立开发者、小团队。
3. 使用：接入项目与需求，确认标准，执行验收，反馈失败证据，修复后复验。
4. 区别：需求、页面行为、失败证据与修复结果可追溯；应用透视图让问题直观可见。
5. 实际成果与范围：填写真实案例数据，明确未覆盖类型，不声称任意项目都可零配置验收。

### IBM Bob Usage Statement

1. Bob 在开发 Ming 时实际完成的阶段与工作。
2. 对应的代码、测试、调试或设计决策证据。
3. 如果实现了 Bob 调用 Ming 的功能，另说明产品运行中的调用与修复过程。
4. 如实际使用 watsonx.ai 或 watsonx Orchestrate，再补充具体用途。截图中的 “If applicable” 不代表必须使用。
5. 如使用其他工具，按事实说明，不能把其他工具或人的工作全部归为 Bob 的贡献。

“Bob 用来开发 Ming”和“Bob 使用 Ming 验收别的项目”是两个层次，说明中不能只写后者而遗漏前者。

## 4. 应用 URL 对本地工具方案的影响

Ming 首先实现本地网页、模型 API、浏览器执行与 Bob 集成。提交字段包含应用平台与应用地址，因此还需单独安排可访问的受控在线样例；不能把远程网页与用户本机执行器视作天然连通。

- 开发初期确认本届指南对在线演示的实际要求，不拖到最后。
- 可以评估在线交互式展示真实历史验收证据，并提供本地完整运行说明；其是否满足赛事要求仍需依据指南确认。
- 在线若只能查看历史证据，必须明确标注，不能让“重新验收”“Bob 修复”等按钮伪装成真实执行。
- 如果要求评委在线执行，安排受控演示项目与相应运行能力，或根据规则调整交付方式。
- 提交前用未登录的独立访问环境检查仓库和应用地址，写明必要的演示访问步骤。

截图未明确“只上传本地录屏可替代应用 URL”，不能默认豁免该项。

## 5. 视频与幻灯片安排

硬要求：MP4 ≤180 秒；至少 90 秒实际运行；包含讲解并明确展示 Bob 的使用。详细的 175 秒时间表已同步到 `MING_BUILD_PLAN.md` 第 12 节。

建议视频实操重点：读需求 → 开始检查 → 发现预置缺陷 → 展开证据 → Bob 读取并修复 → 使用相同标准再次检查。预置缺陷明确标注为演示案例。

建议幻灯片 5–6 页：痛点、用户与方案、应用透视图、Bob 的实际贡献、效果证据、支持范围与后续计划。页数和 PDF 格式只是准备建议，最终以提交表单确认。
